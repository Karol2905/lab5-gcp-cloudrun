Qué es esta aplicación

Una excusa honesta para aprender el ciclo de entrega completo.

El portal de notas es una aplicación web mínima en Node.js con Express. Registra estudiantes con sus calificaciones en la escala colombiana (0.0 a 5.0), calcula el promedio, lo traduce a una escala de letras y dice si aprobó. Nada más.

Esa sencillez es deliberada: el objetivo del laboratorio no es la aplicación, sino todo lo que le pasa alrededor — cómo se instala, cómo se prueba, cómo se empaqueta, cómo llega a Azure y cómo se repite ese camino sin intervención humana. Aun así, la aplicación tiene lo justo para que cada paso tenga sentido: lógica de negocio con casos de frontera, validación que debe devolver 400 y no 500, una sonda de salud que consulta el pipeline, y unas variables de entorno que solo existen cuando corre en la nube.

Cuatro capas, cada una con una sola responsabilidad.

El detalle que más veces rompe el despliegue. App Service arranca el contenedor, le inyecta la variable PORT y espera que el proceso escuche ahí. Si el código fija 3000 a la fuerza, el despliegue termina en verde y el sitio responde «Application Error»: el ZIP llegó bien, pero nadie contesta donde la plataforma pregunta. 
// src/server.js — una línea, dos entornos
const PUERTO = process.env.PORT || 3000;  // en Azure toma PORT; en su máquina, 3000
app.listen(PUERTO);

Pruébelo

Sin peticiones todavía.
Qué observar. Con una nota fuera del rango 0–5 la respuesta es 400 con un mensaje legible, no un 500. La validación vive en src/lib/notas.js y la capa HTTP solo traduce la excepción: por eso la misma regla se puede probar sin levantar un servidor.

bash scripts/empaquetar.sh        # genera deploy.zip
az webapp deploy -g $RG -n $APP \
  --src-path deploy.zip --type zip

Por qué SCM_DO_BUILD_DURING_DEPLOYMENT=false. Con el valor por omisión, App Service ejecuta Oryx dentro del sitio para instalar dependencias otra vez. Eso significa construir dos veces y, peor, construir en un entorno distinto del que usted probó. Como el ZIP ya trae node_modules verificado, se desactiva: se despliega el artefacto, no el código fuente.

La infraestructura, escrita

Terraform no dice «cree»: dice «esto debe existir».

Los recursos de Azure que sostienen esta página no se crearon a mano en el portal: están declarados en infra/main.tf y versionados junto al código. Terraform compara lo declarado con su estado y con lo que realmente hay en Azure, y aplica solo la diferencia.

RecursoPara qué
azurerm_resource_groupEl contenedor lógico y, sobre todo, la unidad de borrado
azurerm_service_planLa capacidad de cómputo. SKU F1: gratuita, sin Always On ni slots
azurerm_linux_web_appEl sitio: runtime de Node, comando de arranque y variables de entorno
random_stringSufijo único: el nombre forma parte de un dominio público global
terraform init      # descarga los proveedores
terraform plan      # muestra QUÉ haría; no cambia nada
terraform apply     # lo ejecuta
terraform apply     # otra vez: "No changes" — eso es idempotencia
La frontera. Terraform gestiona la infraestructura; el pipeline publica el contenido. Son dos ciclos de vida distintos: el sitio cambia pocas veces al año, la aplicación varias veces al día. Si se mezclan, cada apply pelea con cada despliegue.

El pipeline que publicó esta página

Dos jobs, un artefacto entre ellos y una condición que protege producción.

JobCuándo correQué hace
construir-y-probarEn cada push y en cada pull request checkout → setup-node con caché → npm ci → npm test → cobertura → empaquetar → publicar el artefacto
desplegarSolo en main, y solo si el anterior pasó descargar el artefacto → azure/webapps-deploy → prueba de humo contra /health

Entre los dos jobs viaja el ZIP como artefacto, y ese detalle importa: se despliega exactamente el paquete que pasó las pruebas, no uno reconstruido después.

Autenticación sin Service Principal. Una suscripción Azure for Students no suele permitir crear registros de aplicación en Entra ID, así que no hay Service Principal ni OIDC federado. El despliegue usa el publish profile del sitio, guardado como el secreto AZURE_WEBAPP_PUBLISH_PROFILE. Es una credencial de este sitio y solo de este sitio: quien la tenga puede sobrescribir su contenido, pero no tocar el resto de la suscripción.
